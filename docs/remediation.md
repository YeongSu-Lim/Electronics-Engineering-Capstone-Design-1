# 코드 수정·검증 계획

[README](../README.md) · [루트 코드 분석](algorithm.md) · [버전 구분](versions.md) · [후속 검증 기록](followup-20261010.md)

[PR #2](https://github.com/YeongSu-Lim/Electronics-Engineering-Capstone-Design-1/pull/2) 병합으로 후속 코드가 main의 [candidates/20261006/](../candidates/20261006/README.md)에 추가됐습니다. 기존 루트 실행 코드·모델·의존성은 변경하지 않았습니다. 아래는 기존 루트 코드의 문제와 후보의 개선 구현, 운영 전 추가 검증을 구분한 계획입니다.

| 우선순위 | 문제 또는 확인 과제 | 현재 구현 상태 | 남은 검증 |
| --- | --- | --- | --- |
| P0 · 실행 호환성 | HEF 출력의 6개 값 행 구조 가정, 패키지 버전 미고정 | 후보에서도 실제 HEF 출력 구조와의 일치 확인 필요 | 실제 입출력 메타데이터·dtype·색상 순서, 빈 검출·복수 클래스·경계 좌표 확인 |
| P0 · BLE 종료 처리 | 캡처 중단/종료 후 공유 파일의 마지막 위험 출력 잔존 가능 | 후보는 파일 출력 및 유지 시간 구현; 종료 후 무효화·원자적 갱신 미확보 | 수신 측 TTL/중단 정책, 종료·카메라 중단 시 경보 해제 확인 |
| P0 · 판정 근거 | 루트 코드에서 무효 TTC 뒤 과거 평균·횟수 잔존 | 후보는 현재 raw/평균 조건과 무효·축소 시 근거 초기화 구현, 모의 회귀 확인 | 실영상에서 접근 누락과 오경보 함께 평가 |
| P1 · 이력 관리 | 루트 코드의 빈 검출·누락/ROI 이탈 처리 부족 | 후보는 빈 검출 tracker 갱신·누락 초기화·만료·이탈 정리 구현 | 실제 ID 변경·재진입 및 장시간 메모리 사용 확인 |
| P1 · 시간 기준 | 루트 코드는 처리 시각 기반 TTC | 후보는 단조 시간 또는 영상 시간, 중복·역행 처리 구현 | 동일 영상의 처리 속도 변화에 따른 결과 비교 |
| P1 · 장치 통합·기록 | 후보의 MAIN·단일 경보·MP4·CSV·BLE는 루트 진입점과 분리 | 격리 후보로 main에 존재, 관련 모의 검사 통과 | 실제 MP4 재생·프레임 수와 CSV 시간/ID 대응, 무선 수신, 저장 용량 확인 |
| P2 · 성능 근거 | 과거 수치의 시험 버전·표본·정답 미확인, 후보 정확도 미측정 | 신규 성능 수치 없음 | 라벨·설정·시험 분모·FP/FN·처리 지연·메모리를 기록한 별도 실환경 평가 |

후보 코드의 **모의 테스트 34개 통과**와 **하드웨어 담당자가 실제 장비 실행 중 오류 없음을 확인했다는 사용자 전달(2026-10-10 접수)**은 별개의 근거입니다. 전달받은 확인을 직접 검토한 로그·측정 결과로 표현하지 않으며, 실행 버전의 동일성과 기능별 결과는 미확인입니다. TTC·주요 타겟·MP4·CSV·BLE의 실제 정상 동작 및 최신 정확도 측정은 별도로 필요합니다.

과거 약 85%를 후보의 성능으로 사용하지 않습니다. `SAFE/NONE`은 실제 안전 확인이 아니며, 공유 파일 쓰기 성공은 무선 수신 성공이 아닙니다. 루트 코드 대체와 운영 버전 전환은 위 검증 후 별도로 결정합니다.
