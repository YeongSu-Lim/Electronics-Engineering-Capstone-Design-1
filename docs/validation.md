## 증거를 구분하는 기준

| 구분 | 확보 상태 | 문서에서 사용할 표현 |
| --- | --- | --- |
| 현재 main의 구현 | Python 소스·설정·HEF 파일 존재 확인 | 코드에 구현됨 / 정적으로 확인 |
| 과거 자체 시험 | 참여자 설명으로 약 95%→50% 이하→약 85% 확인 | 과거 자체 시험 결과, 독립 재산출 전 |
| 실환경 원본 증거 | 시험 영상·정답 라벨·원시 CSV는 현재 repo에 없음 | 자료 보완 필요 |
| 학술 성과 | 2026 KIIT 하계 대학생 논문경진대회 우수논문상(동상), 제1저자 — 참여자 제공 | 수상 사실과 성능 수치의 검증을 분리 |
| 후속 업데이트 | 별도 ZIP의 코드·문서 확인 | main 미반영, 장치 검증 별도 |

95%는 객체 탐지 mAP로 제시하지 않습니다. 85%는 현재 main 또는 후속 코드의 정확도로 표시하지 않습니다. 표본 수·분모가 없으므로 신뢰구간·정밀도·재현율·정확한 향상률을 새로 산출하지 않습니다.

## 과거 시험 자료 보완 항목

| 필요한 자료 | 확인 목적 |
| --- | --- |
| 시험 날짜·소스 커밋/원본 ZIP·설정 | 각 수치와 구현 버전 연결 |
| 위험 정의·정답 작성 규칙·판정 단위 | 프레임/사건/객체 중 무엇의 정확도인지 명확화 |
| 표본 수·성공/실패 집계·원시 로그 | 결과 재산출 |
| 통제 영상과 야외 영상의 조건 | 객체 종류·카메라 위치·흔들림·조도·접근 방향 구분 |
| 변경 전후 같은 입력에 대한 결과 | 환경 변화와 알고리즘 변화의 효과 분리 |
| 논문 제목·공개 링크·수상 증빙 | 제1저자·수상 내역 검증 |

보고서·사진·영상은 공개 동의와 개인정보를 확인한 뒤 추가합니다. 얼굴·차량 번호·이름·학번·연락처는 공개 목적에 맞게 가림 처리해야 합니다.

## 현재 main 정적 검토 결과

- 설정값·TTC 수식·분기·ROI·경고 경로를 소스와 대조했습니다.
- HEF 출력 후처리는 각 행에 `ymin, xmin, ymax, xmax, score, class_id`가 있다고 가정합니다. 실제 NPU 출력 형태를 장치에서 확인해야 합니다.
- 현재 저장소에는 자동 테스트·시험 로그·의존성 잠금 파일이 없습니다.
- 이 문서 작업에서 실제 Hailo·카메라·장치 통합 실행은 하지 않았습니다.

## 후속 검증 계획 — 아직 성능 측정 전

| 시험 | 조건 | 기록·평가 |
| --- | --- | --- |
| TTC 기초 | 팽창·축소·정지·중복 시간·급격한 박스 변화 | raw/평균 TTC, 필터 사유, 위험 횟수 |
| 추적 연속성 | 빈 검출·ID 변경·ROI 이탈·재진입 | 누락·만료·오경보 지속 여부 |
| 대상 선정 | 복수 위험 객체·등급 변화·MAIN 소실 | 선택 ID·전환 시각·경보 대상 일치 |
| 실환경 반복 | 카메라 흔들림·자세·가림·접근 방향·조도 | 동일 기준 정답 대비 TP/FP/FN 등, 시험 단위 명시 |
| 처리 자원 | 영상 기록 ON/OFF·장시간 실행 | 실제 처리 간격·지연·메모리·저장량·열 상태 |
| 데이터 정합성 | 정상 종료·읽기 실패·프로세스 종료 | MP4 재생·frame_index와 CSV·BLE 데이터 신선도 |

합성 입력·모의 장치 테스트는 로직의 특정 동작만 검증합니다. 실제 카메라·Hailo·영상 인코딩·BLE 무선 통신·실환경 정확도를 대체하지 않습니다. 구현 완료와 장치 시험 완료를 각각 관리합니다.

## 이번 검토에서 실행한 로직 확인

현재 main의 `TTCCalculator`에 시각을 고정한 합성 입력을 주입했습니다. 실제 영상·성능 평가가 아닌 한 가지 회귀 사례입니다.

| 시각 간격 | 폭=높이=하단 y | 출력 | 위험 횟수 |
| --- | --- | --- | --- |
| 시작 | 100 | SAFE · inf | 0 |
| +0.1초 | 110 | CAUTION · 약 1.1초 | 1 |
| +0.1초 | 90 | CAUTION · 약 1.1초 | 2 |
| +0.1초 | 90 | DANGER · 약 1.1초 | 3 |

박스가 축소·정체한 뒤에도 과거 유효 TTC가 평균에 남아 DANGER로 진행하는 사례를 재현했습니다. 위험 횟수와 현재 접근 근거를 함께 관리해야 하는 이유를 보여줍니다. 실행 코드는 수정하지 않았습니다.

별도 후속 ZIP의 `python -m unittest -v test_logic.py test_csv.py test_full.py`도 실행하여 **34개 합성 입력·모의 장치 테스트 통과**를 확인했습니다(2026-10-08). 실제 카메라·NPU·영상 인코더·BLE 무선은 모의 객체 등으로 대체되어 장치 검증을 뜻하지 않습니다. 이 테스트와 후속 코드는 현재 GitHub main에 포함되어 있지 않습니다.
